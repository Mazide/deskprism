# Prism Desk — ESP32-C3

Рабочая прошивка настольного прибора с TFT ST7789 240 × 240 и отражением
в призме. Управление тремя кнопками. Текущая версия: часы, SNAP через Wi-Fi,
помодоро, статистика за день, пользовательский BLE-виджет и Bluetooth.

## Кнопки

- GPIO0: предыдущий экран.
- GPIO1: следующий экран.
- Обе боковые кнопки, удержание 2 секунды: открыть Wi-Fi-портал настройки.
- GPIO2, короткое нажатие: действие экрана. Помодоро — старт/пауза;
  SNAP — запросить обновление (не чаще раза в 5 секунд); Bluetooth — открыть подключение.
- GPIO2, удержание 0,75–2 секунды с отпусканием на экране помодоро: сброс таймера.
- GPIO2, удержание 2 секунды на любом экране: перейти к Bluetooth и открыть
  двухминутное окно подключения. Удержание не вызывает короткое нажатие.

Завершение рабочей фазы видно мигающей надписью на любом экране. Первое нажатие
действия подтверждает сигнал и переносит к помодоро. Следующее запускает перерыв.
Звука нет. Перерывы и рабочие фазы сами не запускаются.

## Bluetooth и компьютер

ESP32-C3 поддерживает Bluetooth LE; обычного Bluetooth Serial/SPP здесь нет.
Имя прибора — **Prism Desk**. Удержать кнопку действия 2 секунды, затем
сопрячь компьютер с прибором, введя шестизначный код с экрана.
Сопряжение сохраняется. Для повторного подключения снова открыть окно кнопкой.
Существующее соединение не разрывается, когда окно подключения заканчивается.
Поддерживается один компьютер одновременно.

GATT использует Secure Connections, шифрование и аутентификацию по коду.
Характеристика записи требует аутентифицированного соединения; ответы также
читаются только после сопряжения. Код не выводится в диагностические логи.

Командный клиент: `tools/prism_client.py`. Нужен Python 3.10+ с `bleak` и
`pyserial`, либо `uv`, который установит зависимости из заголовка скрипта:

```sh
uv run tools/prism_client.py scan
uv run tools/prism_client.py state
uv run tools/prism_client.py widget --title CPU --value '42%' --detail 'MY COMPUTER'
uv run tools/prism_client.py stats --output today.json
uv run tools/prism_client.py sync-time
uv run tools/prism_client.py pomodoro start
uv run tools/prism_client.py pomodoro pause
uv run tools/prism_client.py pomodoro reset
```

При первом подключении используется штатное сопряжение ОС. Если в Linux нет
графического запроса, выполнить `bluetoothctl`, затем `agent KeyboardOnly`,
`default-agent`, `scan on` и `pair <адрес>`, введя код с экрана. Клиент умеет
`--address <BLE-адрес>`, если автоматический поиск неудобен.
Bluetooth-адаптер компьютера должен быть включён.

Произвольный JSON можно отправить через `send`:

```sh
uv run tools/prism_client.py send '{"v":1,"type":"widget","title":"BUILD","value":"PASSED","detail":"MAIN BRANCH"}'
```

Тот же протокол доступен по штатному USB ESP через `--usb /dev/ttyACM1`.
Имя порта может меняться. При открытии USB некоторые драйверы перезапускают
контроллер; клиент сначала проверяет готовность и только затем отправляет
команду изменения состояния. Незавершённый таймер после перезапуска не восстанавливается.
Если USB-подключение оставило плату без изображения/ответа, выполнить команду
с `--reset-usb`: клиент явно перезапустит ESP в обычный режим. Это останавливает
незавершённый таймер. Основной способ обмена данными — BLE.

USB-команда `ble_open` может открыть окно сопряжения и вернуть код владельцу
локального USB-подключения; по BLE код этим способом не возвращается.

## Wi-Fi и SNAP

Основной способ настройки — **Wi-Fi-портал самого прибора**:

1. Если сети ещё нет или за 20 секунд подключиться не удалось, прибор создаёт
   точку доступа **Prism-Setup**. Пароль из восьми символов отображается
   на экране WIFI SETUP. Это временный пароль точки доступа прибора.
2. Подключиться к этой сети с телефона или компьютера.
3. Если страница настройки не открылась сама, открыть **http://192.168.4.1**.
4. Выбрать Configure WiFi, выбрать домашнюю сеть 2,4 ГГц, ввести её пароль
   и нажать Save. Подключение и сохранение выполняет WiFiManager.
5. После успешного подключения точка доступа закрывается, прибор получает
   время и запрашивает SNAP. Обычное подключение к домашней сети восстановится
   автоматически при следующем включении.

Окно настройки открыто 3 минуты. Чтобы открыть его заново или сменить сеть,
удерживать **обе боковые кнопки** (назад и вперёд) 2 секунды. Также доступен
экран WIFI SETUP: короткое нажатие действия открывает портал. Если портал уже
работает, повторное нажатие не меняет его пароль и не сбрасывает подключение.
Настройки старой сети не стираются просто при открытии портала.
Таймеры, кнопки, BLE и экран продолжают работать во время настройки.

На этой ESP32-C3 Super Mini мощность Wi-Fi ограничена до 8,5 dBm.
AP включается до переключения WiFiManager из STA, чтобы ограничение действовало
до начала вещания: при стандартном запуске сеть имела IP, но не была видна
в эфире. После исправления Prism-Setup обнаружена внешним Wi-Fi-адаптером.
Яркость TFT это ограничение не затрагивает.

Дополнительный способ — с компьютера через BLE:

```sh
uv run tools/prism_client.py wifi --ssid 'ИМЯ СЕТИ'
```

Пароль вводится скрыто в локальном терминале, не в командной строке или чате.
Для открытой сети добавить `--open`. Альтернативная настройка по USB:

```sh
uv run tools/prism_client.py --usb /dev/ttyACM1 --reset-usb wifi --ssid 'ИМЯ СЕТИ'
```

Настройки сохраняются в Wi-Fi NVS ESP. Ответ `accepted` по JSON означает
принятие настроек, а не уже состоявшееся соединение. Реальные статусы
подключения, настройки и синхронизации времени выводятся через Scramble.

SNAP запрашивается у Finnhub через HTTPS с проверкой сертификата, раз в минуту.
Для ключа скопировать `secrets.h.example` в `secrets.h` и заполнить
`Secrets::FINNHUB_TOKEN`. Локальный `secrets.h` исключён из Git.
Ключ не выводится в лог. Если его нет — `SNAP KEY NEEDED`.
**Бинарник с локальным ключом не предназначен для публикации.**

Экран показывает цену в USD, дневное изменение и дату/время котировки
провайдера (`LAST`). Это последняя доступная котировка, не обещание потока
реального времени. При потере сети/отсутствии успешного обновления более трёх
минут последнее значение сохраняется с отметкой `CACHED / OLD DATA`.
Без полученной котировки показываются прочерки; выдуманных цен нет.
Wi-Fi и HTTPS работают в отдельной задаче, не блокируя кнопки и таймер.

На подключённой плате подтверждены Wi-Fi, синхронизация времени и получение
реальной котировки SNAP по HTTPS.

## Помодоро и статистика

По умолчанию 25 минут работы и 5 минут отдыха. Таймер работает в фоне при смене
экрана. Завершённая рабочая фаза добавляет одну сессию и её длительность;
паузы, сбросы, незавершённые сессии и перерывы в статистику фокуса не входят.

Статистика хранится во Flash через Preferences/NVS, namespace `prism-widgets`,
ключ `stats-v1`. Снимок записывается при завершении рабочей сессии, без записи
на каждом кадре или секунде. При ошибке сохранения отображается статус ошибки,
запись повторяется с интервалом 5 секунд. NVS сохраняется при обычной прошивке
и отключении питания. Очистка всей Flash удаляет данные и параметры сети.

Хранятся общие счётчики, последние семь дат с сессиями и отдельный счётчик
завершённых сессий без известной даты. Экран TODAY показывает только текущую
дату. Завершение относится к дате окончания рабочей фазы, включая переход через
полночь. Без достоверного времени сессия сохраняется как UNDATED и позже
автоматически не приписывается сегодняшнему дню.

Дата получается через NTP после Wi-Fi или команду `sync-time` с компьютера.
Часовой пояс — Великобритания с летним временем. Отдельного RTC нет;
после отключения питания время нужно получить заново. Активный таймер после
включения начинает с остановленных 25 минут; завершённая статистика сохраняется.

Длительность можно задать до запуска:

```sh
uv run tools/prism_client.py pomodoro configure --work 25 --break-min 5
```

Диапазоны — 1–180 и 1–60 минут. Настройка отклоняется у работающего таймера,
у остановленного сбрасывает текущий отсчёт. Длительности пока не сохраняются
между включениями. Экспорт статистики — `stats --output today.json`.

## Формат JSON v1

В RX передаётся одна компактная JSON-строка с завершающим `\n`, максимум
383 байта без перевода строки. BLE-запись можно разбивать на фрагменты;
клиент использует пакеты по 20 байт, совместимые с базовым MTU.
Вложенные переносы строк в тексте виджета не поддерживаются.
Поля заголовка, значения и подписи виджета — до 20 печатных ASCII-символов.

- Service: `6e400001-b5a3-f393-e0a9-e50e24dcca9e`
- RX (write with response): `6e400002-b5a3-f393-e0a9-e50e24dcca9e`
- TX (read, до 512 байт): `6e400003-b5a3-f393-e0a9-e50e24dcca9e`

`v:1` обязательно, `id` — необязательный uint32 для сопоставления ответа.
После записи клиент читает TX до ответа с тем же `id`; успешный GATT write
сам по себе ещё не подтверждает выполнение команды.

```json
{"v":1,"id":1,"type":"widget","title":"CPU","value":"42%","detail":"DESKTOP"}
{"v":1,"id":2,"type":"wifi","ssid":"NETWORK","password":"PASSWORD"}
{"v":1,"id":3,"type":"time","unix":1792670400}
{"v":1,"id":4,"type":"pomodoro","action":"start"}
{"v":1,"id":5,"type":"get","what":"state"}
{"v":1,"id":6,"type":"get","what":"stats"}
```

Ответы содержат `v`, `id`, `ok` и данные/поле `error`. Поле `saved` в статистике
показывает, сохранён ли текущий снимок. Wi-Fi-пароли и API-ключ в ответы не входят.
Пользовательский виджет обновляется в RAM и не сохраняется после питания.

## Экран и распиновка

| Назначение | GPIO / питание |
| --- | --- |
| TFT SCK | 5 |
| TFT MOSI | 4 |
| TFT CS | 7 |
| TFT DC | 20 |
| TFT RST | 21 |
| TFT VCC, BLK | 3V3, подсветка постоянно включена |
| Назад / вперёд / действие | 0 / 1 / 2 ↔ GND, INPUT_PULLUP |

Контроллер ESP32-C3 Super Mini, Flash 4 МБ. Логический холст RGB565 120 × 120
зарезервирован статически (28 800 байт) и выводится на 240 × 240 в масштабе ×2.
Это оставляет память для BLE, Wi-Fi и TLS. Шрифт — пиксельный Adafruit GFX.
Весь вывод зеркалируется и поворачивается на 90° против часовой стрелки для
призмы над экраном. Яркость изображения усилена (`imageGain`, `imageGamma`);
подсветка BLK программно не регулируется.

Корпус — белый клин 25°, съёмная решётка и верхняя TFT-кассета, чёрная накладка
кнопок со шевронами. Призма номинально 30 × 30 × 30 мм. Аккумулятора,
RTC с батарейкой и звука нет. USB breakout передаёт только питание через
тумблер на 5V ESP; не подключать два источника USB одновременно.
Прошивка — через штатный USB-C самой ESP.

## Сборка и проверка

Arduino core ESP32 3.3.11; библиотеки Adafruit GFX, Adafruit ST7735/ST7789,
ArduinoJson 7, NimBLE-Arduino 2.5.1, WiFiManager. Секрет Finnhub остаётся локальным.

```sh
arduino-cli compile --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=huge_app \
  --build-path /tmp/prism_desk_widgets_build .
```

Host-тесты проверяют фоновые таймеры, паузу, переходы фаз и даты, undated,
кольцевую историю, переполнение millis, фрагментацию/переполнение сообщений,
валидацию JSON, смену статусов и завершение Scramble.

```sh
g++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -I"$HOME/Arduino/libraries/ArduinoJson/src" tests/device_model_test.cpp -o /tmp/prism_model_test
ASAN_OPTIONS=detect_leaks=0 /tmp/prism_model_test
g++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
  tests/status_display_test.cpp -o /tmp/prism_status_test
ASAN_OPTIONS=detect_leaks=0 /tmp/prism_status_test
```

На ESP и компьютере проверены защищённое BLE-сопряжение, передача виджета,
чтение состояния и статистики, старт/пауза/сброс таймера. После перезапуска
повторно проверены сохранённое сопряжение, синхронизация времени по BLE и
правильная дата TODAY. В конце проверки помодоро оставлен остановленным
на 25:00, тестовых сессий нет. Проверка завершения
фазы и дневных счётчиков выполнена в host-тестах; тестовых завершённых сессий
в пользовательскую статистику не добавляли. Реальный HTTPS-запрос SNAP и временный показ BLE-карточки с возвратом через
8 секунд проверены на устройстве. Сохранение завершённой сессии после полного
рабочего интервала ещё предстоит проверить на устройстве.

## Сохранённые варианты

Предыдущая рабочая версия LOADING и её бинарники — `checkpoints/loading_only/`.
Старые призма, огонь и галактика остались исходниками/предпросмотрами и в текущую
прошивку не входят. Лицензия эффекта Scramble — `THIRD_PARTY_NOTICES.txt`.

Входящая BLE-карточка показывает виджет на 8 секунд и возвращает предыдущий
экран. Следующая карточка продлевает показ. Если виджет выбран вручную, он
остаётся открытым. Нажатие кнопки отменяет автоматический возврат.
